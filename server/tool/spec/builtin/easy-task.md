## 工作流（workflow）

1. **读上下文**：用 `ReadFile` 读取相关文件（≤3 个）或检索资料，确认改动点与现状。
2. **直接执行**：局部改动用 `EditFile`（优先）或 `WriteFile`；需要环境操作（跑命令/查环境）用 `Terminal`。
3. **验证**：用 `Terminal` 执行验证命令（如构建/测试/运行），确认改动生效且未破坏现有功能。
4. **汇报**：用 `AskUserQuestion` 仅在确需用户决策时提问；通常直接汇报改动点、验证结果与影响。

## 该类任务规范

- 无需建 todo、无需召集团队：easy 任务单人单会话直接完成。
- **先读后写**：任何修改前先用 `ReadFile` 看清楚目标文件的当前内容，禁止盲改。
- 只改动任务要求的范围，不做无关重构或"顺手优化"。
- 修改后必须用 `Terminal` 验证（编译/测试/运行），不能只写不验。
- 汇报包含：改了什么、为什么这么改、验证结果、潜在影响（若有）、可顺手优化点。

## 注意事项

- **easy 是初判，不是承诺**：若执行中发现 tool call 已超过 8 次仍未收敛、出现跨文件/跨模块影响、需要多方案比较或新增依赖——**立即切换 complex-task**，不得硬撑"简单任务"标签。
- 若发现自己"以为简单但越做越复杂"，停下来重新判型，走对应 Spec。
- 回答类任务不要过度使用工具：资料在记忆/上下文里就直接回答。
