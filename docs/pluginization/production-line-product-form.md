## 1. 一句话定位

**生产线是一个「只做决定」的工作台：用户每天花 20 分钟分发任务、回答必须由人回答的问题、
看产出；其余时间它自己按队列推进，并把每一次自动决定记在台账里。**

它不是聊天界面，也不是任务管理器的换皮：它把「准备 → 执行 → 复盘」固定成一条流水线，
用户只在三个位置出现：**拍板、处理异常、验收产物**。

### 1.1 核心差异：10 秒图谱理解

**传统 Agent 是「边聊边查」：先问一句，再翻文件、读文档、猜影响面，理解要几轮对话才成形。**
生产线的差异在需求提交后的第一屏：

> **10 秒内给出一张有证据的「理解卡」，让用户立刻进入语义对齐；深化可以在后台继续。**

- **图谱先于模型**：第一版理解由项目图谱检索 + 模板组装完成，不把 LLM 放在 10s 关键路径上。
- **证据先于结论**：每条影响面/复用/约定都带 `path:line` 或文档锚点，没有证据的只进「未知」。
- **真实全面**：覆盖代码结构、相似实现、文档约定、变更、测试与风险六个维度，并显式列未知；
  不承诺「读完全部代码」，但承诺「不编、不漏关键面」。
- **快但不浅**：10s 是首个可对齐版本；后台「深化侦查」继续补证据，更新同一张卡。
- 后面的打包/执行与传统 Agent 差异不大，**理解速度与可信度才是产线的护城河**。

### 1.2 六条设计原则

| # | 原则 | 落到界面 |
| --- | --- | --- |
| 1 | **决定优先** | 默认页先列「待你决定」，再列异常、在跑、刚完成；不先展示全部任务 |
| 2 | **不聊天** | 没有输入框式对话；交互只有表单、问题卡、按钮与报告 |
| 3 | **失败可见** | 任何 `blocked` 必须在首屏出现，带原因、对应 run 与下一步动作 |
| 4 | **安全默认** | 写域、禁区、预算、并行、重试默认收紧；危险动作要显式确认 |
| 5 | **事实在盘上** | UI 只投影 `task.yaml / runs / inbox`；刷新/重连以磁盘状态为准 |
| 6 | **可回退** | 暂停、恢复、取消、重试都在界面上；不要求用户改 YAML 或敲命令 |

## 2. 用户的一天（三个真实场景）

### 2.1 周一 20 分钟：分发

1. 打开产线 → 「今日」显示「还没有任务」→ 点「开始准备」。
2. 填需求五栏（目标/现状/验收/禁区/期限）→「开始理解」。
3. **10 秒内**出现理解卡：一句话理解、影响面、既有实现、约定、风险、未知与 3 个待拍板问题。
4. 直接逐条回答（每题有推荐项与不选后果）→「全部按推荐」；后台深化继续补证据。
5. 看范围与任务计划，改一条写域 →「确认并落档」。
6. 摘要出现：3 个任务、2 个可并行、门控命令 `dart analyze` →「开始执行」。
7. 关掉窗口。产线自己跑。

### 2.2 周三 5 分钟：处理异常

1. 打开产线 → 首屏「需要处理」：`T7 已阻塞 · 门控失败`。
2. 点开详情 → 「执行与门控」看到 2 个 analyze 错误 →「重试」。
3. 回到「今日」，任务重新进入 `running`；关窗口。

### 2.3 周五 5 分钟：验收

1. 打开产线 →「刚完成」列出 3 个 `done`，每条带门控结果。
2. 点「产物」→ 打开 `acceptance.md` 与 `pack.md`（落到文件窗）。
3. 看台账：token、耗时、每次决策动作；关窗口。

## 3. 信息架构

```text
左活动栏「生产线」
└─ 左栏：产线列表（名称 / 健康点 / 待决定数 / 在跑数）
   └─ 中栏：产线工作台（唯一主界面）
      ├─ 今日（默认）
      ├─ 准备（未完成时常驻入口）
      ├─ 执行（任务看板；点行在右栏打开详情页）
      └─ 工具（台账 / 产物 / 整理报告 / 逻辑去重）
   └─ 右栏窗口：文件浏览、任务详情、设置、插件管理等（任务详情为产线新增窗口）
```

- **不新增第五个活动栏项**，沿用现有第 4 项「生产线」。
- **任务详情放右栏详情页**：点任务行在右栏打开「任务详情」窗口（复用 `RightPanelHost`，
  `preferredWidth ≈ 520`），与文件窗、设置窗同一套窗口切换；中栏不再做内联抽屉。
- **左栏只选产线**，不放任务列表；所有任务操作在中栏。

## 4. 工作台骨架

### 4.1 产线头（永远可见）

```text
┌ 标准开发流 · E:/work/project                         [配置] [暂停/恢复] [立即决策] ┐
│ 执行中 · 3/8 完成 · 预算 12.4k/100k · 主控：10:32 continue · 连续失败 0            │
└──────────────────────────────────────────────────────────────────────────────────┘
```

| 元素 | 口径 |
| --- | --- |
| 状态 | 后端计算：`准备中 / 执行中 / 空闲 / 已暂停`；`需要你` 是叠加徽标，不写盘 |
| 进度 | `done / 非 cancelled 总数`；准备阶段显示「第 2 步 / 4」 |
| 预算 | 用量 / 上限；未设上限显示「不限」；到点后变红并显示「已软停」 |
| 主控 | 最近一次动作与时间；`连续失败 > 0` 时变黄，`paused` 时显示原因 |
| 动作 | 配置、暂停/恢复、立即决策；准备未完成时「立即决策」禁用 |

### 4.2 四个入口

| 入口 | 何时默认 | 内容 |
| --- | --- | --- |
| **今日** | 永远默认 | 待你决定 → 需要处理 → 正在跑 → 刚完成 |
| **准备** | 有 `draft/recon/aligning/awaiting_user` 任务时高亮 | 四步流程（§5） |
| **执行** | 有执行期任务时高亮 | 任务看板 + 详情抽屉（§6） |
| **工具** | 手动进入 | 台账、产物、整理报告、逻辑去重（§7） |

> `今日` 是「20 分钟入口」，`准备`/`执行` 是「做事入口」，`工具` 是「排障与审计入口」。
> 三者共用同一份数据，不做三套状态。

### 4.3 今日（默认页线框）

```text
┌ 待你决定 (2) ───────────────────────────────────────────────────────────────┐
│ [准备] T3 验收标准以哪份文档为准？   推荐 A · 不选后果：…   [按推荐] [回答]     │
│ [运行] T5 依赖版本选 1.2 还是 1.3？  推荐 1.3 · 影响：…      [回答]            │
├ 需要处理 (1) ───────────────────────────────────────────────────────────────┤
│ T7 已阻塞 · 门控失败（dart analyze 2 个错误）        [查看原因] [重试] [取消]  │
├ 正在跑 (2) ─────────────────────────────────────────────────────────────────┤
│ T2 执行中 · 12m · 8.2k tokens      T4 打包中 · 3m                            │
├ 刚完成 (3) ─────────────────────────────────────────────────────────────────┤
│ T1 会话列表过滤 · done · 门控通过 · 2 个产物           [打开产物]              │
└──────────────────────────────────────────────────────────────────────────────┘
```

- 每个分区最多 5 条，超出「查看全部」跳到对应入口。
- 卡片操作就地完成，不弹全屏对话框；回答/查看原因用行内展开或详情抽屉。
- `done` 只出现最近 5 条，更早去「工具 → 台账」。

## 5. 准备阶段（需求 → 10s 理解 → 对齐 → 计划）

```text
[1 需求] ── [2 理解 ≤10s] ── [3 对齐] ── [4 计划]
图谱：就绪（3 分钟前） · 覆盖 42 包 / 318 文件 / 1,204 文档块 / 96 代码块
窗口：本轮剩余 12:40（仅提示，可离开；未答跨日保留）
```

### 5.1 第 1 步：需求五栏

| 栏 | 必填 | 交互 |
| --- | --- | --- |
| 目标 | 是 | 单行；空泛词（优化/重构/差不多/尽快）给可点选改写建议 |
| 现状 | 否 | 多行 |
| 验收 | 是 | 多行；至少一条可判定标准 |
| 禁区 | 否 | 多行；默认继承 `policy.deny_globs`，只展示不改 |
| 期限 | 否 | 文本；不解析成时间，只作为提示 |

底部：`保存草稿`、`开始理解`。目标或验收为空时禁用并说明缺哪栏。

### 5.2 第 2 步：10 秒图谱理解

#### 5.2.1 延迟 SLO（硬指标）

| 指标 | 口径 |
| --- | --- |
| **起点** | 用户点「开始理解」且五栏通过校验 |
| **终点** | 理解卡首版可交互（含影响面、证据、首轮问题） |
| **SLO** | **P50 ≤ 3s，P95 ≤ 10s**；超过 10s 必须出「部分结果」，不得空屏 |
| **不计入** | 后台深化、LLM 润色、问题重排 |

预算拆解（关键路径无 LLM 调用）：

| 阶段 | 目标 | 说明 |
| --- | --- | --- |
| 骨架渲染 | ≤0.3s | 立即回显需求 + 进度条 |
| 图谱检索 | ≤2.0s | 包图 + 文档 BM25 + 代码块向量（最多一次 embedding 查询） |
| 证据组装 | ≤1.0s | 去重、排序、补 `path:line`、算覆盖 |
| 理解卡渲染 | ≤0.7s | 模板化文本，不调模型 |
| 首轮问题 | ≤0.5s | 规则生成（范围歧义/验收缺失/文档冲突/风险命中） |
| **合计 P95** | **≤5s** | 预留 5s 给机器抖动；10s 是硬上限 |

#### 5.2.2 理解卡

```text
┌ 我的理解（图谱侦察 · 4.2s · 索引 3 分钟前） ─────────────────────────────┐
│ 一句话：让会话列表按项目过滤，改左栏数据源与过滤状态，不碰数据库。          │
│                                                                            │
│ 影响面  packages: tree.ui.default                                          │
│         files: lib/ui/widgets/agent_list.dart:88 · lib/ui/models/...       │
│         入口: AgentList.build / _filteredSessions                          │
│                                                                            │
│ 既有实现  AgentList 已有 projectId 字段（agent_list.dart:88）               │
│           相似块 3 个（agent_list.dart:120 / :204 / team_scope_view.dart:41）│
│                                                                            │
│ 约定      docs/pluginization/ui-*.md#圆角 · work-log 2026-11-12 条目        │
│                                                                            │
│ 风险      写域与在途 T2 交叠；known-issues #47 首屏性能；无 embedding 降级   │
│ 未知      测试覆盖方式未定；项目未启用 embedding（lexical）                  │
│                                                                            │
│ 待你决定 (3)  Q1 过滤状态存本地还是会话？ Q2 验收用哪组用例？ Q3 …           │
│ [进入对齐]  [深化侦查]  [重新理解]                                          │
└────────────────────────────────────────────────────────────────────────────┘
```

- 每条影响面/复用/约定/风险都能点开证据（文件行或文档锚点）；没有证据的只能进「未知」。
- 「一句话理解」允许规则模板先生成，LLM 润色回来后就地替换，不阻塞对齐。
- 首轮问题在 10s 卡内即可回答；深化回来只追加「新增证据 / 新问题」，不改已答问题。

#### 5.2.3 「真实全面」= 六维覆盖，不是读完全部代码

| 维度 | 图谱来源 | 卡片呈现 |
| --- | --- | --- |
| 代码结构 | `docnorm.scan` 的 `pkg_index`（包/子包/入口/依赖） | 影响包、子包、入口符号 |
| 相似实现 | 产线 dedup 的 `dedup_chunks` / `dedup_vectors` | top-k 相似函数块 + `path:line` |
| 文档约定 | `docnorm` GraphRAG 的 chunk / 社区报告 | 相关章节、决策、约定 |
| 变更上下文 | `git status` / 近期 `git log` | 已改文件、近期同区工作 |
| 测试关联 | 文件路径映射（`test/` ↔ `lib/`） | 可能受影响的测试 |
| 风险与未知 | known-issues / TODO / `deny_globs` / 写域交叠 | 风险条目 + 显式未知 |

底部固定显示覆盖读数：`包 42 / 文件 318 / 文档块 1,204 / 代码块 96 / 未覆盖 7`。
覆盖不足时如实标 `partial`，不把「没查到」说成「不存在」。

#### 5.2.4 图谱来源与新鲜度

| 来源 | 版本键 | 新鲜度 |
| --- | --- | --- |
| 包图 `pkg_index` | workspace HEAD + scan 版本 | HEAD 变化则后台增量重扫 |
| 文档图 `graph_*` | `doc_state` 指纹 + chunk 版本 | 文档变更则增量重建 |
| 代码块/向量 `dedup_*` | `baseline_sha` + 模型/分块版本 | `git diff --name-status -M` 增量 |
| 变更/测试 | 当前 `git status` | 实时 |

- 理解卡显示「索引时间 + 是否 stale + 变更文件数」；stale 时仍可用，但标黄。
- **预 warm**：建线 / 选中产线 / 工作空间变化时后台建一遍索引；提交需求优先读缓存。
- 缓存 `understanding/<requirementHash>_<graphVersion>.json` 属插件数据，可重建，不手改。

#### 5.2.5 冷启动与降级

- **索引未就绪**：10s 内先出「结构版理解」（包图 + 文档清单 + 风险），
  代码相似维度标「构建中」，后台完成后在同一卡片补上；**不阻塞进入对齐**。
- **无 embedding 模型**：检索降级 lexical，卡片标 `degraded: lexical`；不静默冒充 hybrid。
- **图谱缺失 / docnorm 不可用**：按既有依赖 fail-closed，给出缺失项，不伪造理解。
- **超时**：到 10s 停止等待，输出已就绪部分 + `partial: true` + 缺失维度；用户可先对齐。

#### 5.2.6 深化侦查（后台）

- 用户点「进入对齐」后，深化继续跑：读点状文件、补文档章节、扩展图谱 1~2 跳。
- 深化只追加证据与「新问题」，不改已答问题；更新卡片顶部显示「新增 N 条证据」。
- 深化不计入 10s SLO，也不阻塞落档；用户可随时关闭。
- 深化受读取预算约束（现有 `prepare.read`：文件 ≤ 8 / grep ≤ 2 轮）。

### 5.3 第 3 步：对齐

每个 `Q` 一张卡：

```text
Q1 验收以哪份文档为准？                     [默认 A] [推荐 A]
A. docs/project-status.md
B. docs/work-log.md
不选后果：将按 A 执行，索引可能缺少历史口径。
[选择 A] [选择 B] [其它…]
```

- 一次最多 N 条（设置默认 3），超出截断并显示「还有 N 条未展示」。
- 首轮问题在 10s 理解卡里就能回答，不等深化；深化新增的问题进入下一轮。
- `全部按推荐` 只对准备阶段问题生效，必须用户点击。
- 有未答问题时，第 4 步「确认并落档」置灰，并显示还差哪几题。
- 离开页面不丢；窗口关闭后任务转 `awaiting_user`，下次继续。

### 5.4 第 4 步：计划与落档

```text
范围：in … / out … / 明确不做 …
任务计划
T1 会话列表按项目过滤   依赖 -    写域 lib/ui/widgets/agent_list.dart   验收 dart analyze
T2 会话列表测试         依赖 T1   写域 test/                            验收 dart test
[编辑任务] [删除] [新增任务]
[确认并落档]（2 题未答，暂不可用）
```

- 任务行可编辑：标题、`kind`、依赖、读写域、验收；保存前校验依赖闭环与写域非空。
- 落档前预览将写入的项目资产清单（`recon/scope/plan/decisions/...`）。
- 落档后展示 ≤10 行分发摘要 + `开始执行`（或按拍板自动启动）。
- 落档后的任务与手建任务完全同构，后续可在「执行」里继续改计划字段。

## 6. 执行阶段

### 6.0 任务输入与派发（手建任务）

**现状缺口**：UI 建任务只有「标题 + 写域」，没有任务内容、验收判据、依赖、附件与引用；
后端 `task.yaml` 已经有 `intake / acceptance / read_scope / depends_on`，但没有编辑契约与附件通道。
本节把「任务是什么」补成可执行输入，而不是只有一行标题。

#### 6.0.1 任务输入字段

| 字段 | 必填 | 用途 |
| --- | --- | --- |
| `title` | 是 | 列表与台账识别 |
| `brief` | 派发前必填（或 `intake.goal` 非空） | 任务内容 / 要求，Markdown；打包与执行提示词的第一段 |
| `acceptance` | 派发前至少 1 条 | 门控之外的人可读验收判据 |
| `write_scope` | 否 | 默认 `**`（整个工作空间，串行、禁区照拦） |
| `read_scope` | 否 | 参考范围；添加 `references` 时自动并入 |
| `references` | 否 | 工作空间内已有文件路径（不复制）；自动并入 `read_scope` |
| `attachments` | 否 | 上传到 `.input` 的只读输入（设计稿/文档/图片） |
| `depends_on` | 否 | 依赖任务 id；未 `done` 不派发 |
| `priority` | 否 | 默认 50；队列排序 |
| `kind` | 否 | `conventional / special`；影响提示词措辞 |
| `intake` | 否 | 准备阶段五栏；有值时作为「需求模板」只读展示并进入提示词 |

规则：

- `brief` 是手建任务的主输入；准备阶段落档的任务可以把 `plan.md` 的任务摘要写入 `brief`，
  同时保留 `intake` 作为背景。
- `acceptance` 与 `gate` 分开：前者给人看/给模型对齐，后者是真正跑的命令；
  没写 `gate` 时仍按 `pack.baseline` → `dart analyze` 兜底。
- 附件是**只读输入**，不参与写域判定，也不会被 `deny_globs` 拦截；写域只约束执行期改动。

#### 6.0.2 新建 / 编辑表单

```text
┌ 新建任务 · T3 ────────────────────────────────────────────────────────────────┐
│ 标题   [ 会话列表支持按项目过滤                                        ]        │
│ 内容   [ Markdown：要做什么、现状、边界……                    ] [预览]          │
│ 验收   [+ 添加判据]  · dart analyze 无新增  · 相关用例全绿                     │
│ 范围   写域 [ ** ]（默认整个工作空间）   读域 [ lib/ui/, lib/io/ ]             │
│ 依赖   [ T1 × ]  优先级 [50]  类型 [常规 ▾]                                    │
│ 附件   [上传文件] [引用工作区文件]                                              │
│        [🖼 design.png 240 KB ×] [📄 notes.md 12 KB ×] [📕 spec.pdf 1.2 MB ×]   │
│ 提示   图片需要打包/执行模型支持视觉；PDF/Office 首版仅存储与预览，不自动读取。   │
│                                        [保存草稿] [创建并加入队列] [创建并开始] │
└────────────────────────────────────────────────────────────────────────────────┘
```

- 内容用多行 Markdown；`预览` 复用现有 Markdown 渲染，不引入富文本编辑器。
- `创建并加入队列`：校验通过后建 `queued` 任务；产线开着自动推进时由下一次决策接手。
- `创建并开始`：建任务后立即触发一次「开始执行」（等价于切到执行页点一次）。
- `保存草稿`：建 `draft`，允许内容/验收不完整；补齐后才能入队。
- 附件支持选择本地文件、拖拽、粘贴截图；预览复用消息输入框的附件卡。

#### 6.0.3 附件支持矩阵

| 类型 | 预览 | 模型是否可读 | 首版口径 |
| --- | --- | --- | --- |
| Markdown / 文本 / 代码（md/txt/json/yaml/csv/dart/py/ts…） | 文本 | ✅ `read` 工具 | 完整支持；提示词只给路径与大小，不整篇塞入 |
| 图片（png/jpg/jpeg/webp/gif） | 缩略图 | ✅ 仅当角色模型支持视觉 | 走 `tree.agent` 现有 vision 通道；不支持时界面预检警告 |
| PDF | 现有 PDF 预览 | ❌ 首版不抽取正文 | 存储 + 预览；提示词标「不可直接读取」 |
| Office（docx/xlsx/pptx） | 否 | ❌ 首版不抽取正文 | 存储；提示词标「不可直接读取」 |
| 其它二进制 | 文件名/大小 | ❌ | 存储；提示词标「不可直接读取」 |

限制（v1 常量，后续可进 `limits`）：

- 单文件 ≤ 20 MB、单任务 ≤ 50 MB、最多 20 个附件；
- 只接受普通文件，拒绝目录、符号链接与工作空间外路径；
- 同名文件自动加 `-1/-2` 后缀，不覆盖已有附件；
- 图片内联沿用项目既有约束（长边 360–1024、单请求体上限），超限走引用而不是硬塞。
- **首版允许「只存不读」**：PDF/Office/其它二进制与非视觉模型下的图片只落盘与预览，
  不抽取正文、不伪造描述；该取舍登记为 known-issues #51，抽取能力后续单独立项。

#### 6.0.4 存储与上传流程

**存储位置**（工作空间 `.input`，不进项目资产、不随 git 提交；用户 2026-11-14 拍板）：

```text
<workspace>/.input/production_lines/<line_id>/tasks/<task_id>/attachments/<name>
```

`task.yaml.attachments` 记录元数据：

```yaml
attachments:
  - name: design.png
    path: .input/production_lines/pl_.../tasks/T3/attachments/design.png
    size: 245760
    type: png
    sha256: 9f2c...
    added_at: 2026-11-14T10:00:00+08:00
```

**上传流程**（不传二进制经产线插件，复用既有分片通道）：

1. UI 用现有 `uploadFileChunked` 把本地文件传到产线工作空间（files 插件 `line:<lineId>` 作用域），
   落点仍是 `.input/{yyyymmdd}/...`；拿到工作空间相对路径。
2. UI 调 `production.task.attach`（或建任务时带 `attachment_sources`），传 **工作空间相对路径**；
   插件校验来源必须在 `.input/` 或本线资产目录内。
3. 插件复制到 `.input/production_lines/<line>/tasks/<task>/attachments/`，计算 `sha256/size/type`，写回 `task.yaml`，
   删除 `.input/{yyyymmdd}/` 临时件；返回完整任务。
4. 失败（超限/越界/文件名非法）在表单内就地报错，已上传的临时件由插件清理。

> 不把本机绝对路径交给插件：即使当前是本地工作空间，也保持与 SSH 工作空间一致的
> 「先上传、再登记」口径，避免以后换远端执行时重做。

#### 6.0.5 派发前预检（UI 与后端同判据）

| 检查 | 不通过时 |
| --- | --- |
| 标题非空 | 禁止保存 |
| `brief` 或 `intake.goal` 非空 | 「任务还没有内容」 |
| `acceptance` ≥ 1 条 | 「至少写一条验收判据」 |
| 执行 Agent / 执行模型存在 | 「先配置执行 Agent 与模型」 |
| 工作空间存在且是 git 仓 | 警告：可打包，但无法判写域（执行会被拒） |
| 附件都存在且 `sha256` 一致 | 「附件已变化，请重新上传」 |
| 图片附件 + 模型无视觉 | 警告并要求确认「图片仅作人工参考」 |
| `depends_on` 未满足 / 写域交叠 / 并行满 | 不派发，给 `waiting_on` / `with_task` |

#### 6.0.6 提示词组成

打包与执行共用同一段任务输入（顺序固定）：

```text
任务：T3 会话列表支持按项目过滤
内容：
<brief>

需求模板（如有）：
目标 / 现状 / 验收 / 禁区 / 期限

验收判据：
- dart analyze 无新增
- 相关用例全绿

附件（只读）：
- [text] notes.md · 12 KB · docs/production_lines/.../notes.md（可用 read）
- [image] design.png · 240 KB · docs/production_lines/.../design.png（仅视觉模型）
- [binary] spec.pdf · 1.2 MB · docs/production_lines/.../spec.pdf（不可直接读取）

引用文件：
- docs/project-status.md
- lib/ui/widgets/agent_list.dart

项目文档（docs.memory_manifest 摘要）：
<projectContext>

记忆（agent.memory.get 返回，原样）：
<memory.text>

写域：lib/ui/widgets/agent_list.dart
读域：lib/ui/, docs/project-status.md
```

- 打包提示词带完整任务输入；执行提示词带同一段 + `pack.json` + `acceptance.md`。
- 执行期主控仍只看快照，不读附件正文；附件只影响打包/执行的提示词。
- `pack.json` 记录附件快照（`path + sha256`）；执行前校验，变了就拒跑并要求重打包。

#### 6.0.7 编辑边界

| 任务状态 | 可改内容/验收 | 可改附件/引用 | 可改范围/依赖 |
| --- | --- | --- | --- |
| `draft` | ✅ | ✅ | ✅ |
| `queued` / `blocked` / `awaiting_user` | ✅ | ✅ | ✅ |
| `packed` | ⚠️ 需重新打包 | ⚠️ 需重新打包 | ⚠️ 需重新打包 |
| `packing` / `running` / `gating` | ❌ | ❌ | 仅优先级/依赖 |
| `done` / `cancelled` | ❌ | ❌ | ❌ |

改内容/附件/范围后：`packed → queued` 并提示「已失效的打包结果需要重跑」，不静默复用旧包。

#### 6.0.8 接口与数据改动

| 层 | 改动 |
| --- | --- |
| `task.yaml` | 新增 `brief`、`attachments[]`、`references[]`（加法键，旧任务缺省为空） |
| `production.task.create/update` | 接受上述字段；`update` 按 §6.0.7 状态边界校验 |
| 新命令 `production.task.attach/detach` | 登记/移除附件；来源限 `.input/` 或本线资产目录 |
| REST | `POST/DELETE /api/production/lines/{id}/tasks/{taskId}/attachments`；建任务接受 `attachment_sources` |
| 提示词 | `packerUserPrompt` / `executorUserPrompt` 增任务内容、附件、引用、项目文档与记忆段 |
| 记忆 | `tree.agent` 新增 `agent.memory.get/record`；产线只加 `MemoryPort` 适配器与 run 台账 `memory_hash/sources` |
| `pack.json` | 增 `attachments[{path,sha256,size,type}]` 快照 |
| `tree.agent` | `agent.worker.run` 增可选 `attachments`；`SubagentTurnRequest` 透传到现有 vision 通道 |

#### 6.0.9 验收

1. 新建任务填内容 + 2 条验收 + 1 张图 + 1 个 md，附件立即出现在表单，保存后落到 `.input`；
2. 只填标题保存可建草稿，但「加入队列/开始」被拒并指出缺内容/验收。
3. 文本附件能被打包模型 `read`；图片在支持视觉的模型下进入多模态，非视觉模型有预检警告。
4. PDF/Office 附件有「不可直接读取」标识，不伪造内容。
5. 打包后改附件 → 任务回 `queued` 并提示重打包；旧包不再被执行。
6. 附件路径越界、超限、同名覆盖、目录/符号链接均被拒。
7. 执行提示词包含任务内容、附件清单与引用文件；改动不依赖手改 YAML。

### 6.1 任务看板

```text
[全部] [进行中] [待你决定] [阻塞] [已完成]        [按计划派发] [暂停产线]
T1  done       门控通过 · 2 个产物
T2  running    执行中 · 第 1 次 · 8.2k tokens
T4  packing    打包中 · 3m
T7  blocked    门控失败 · dart analyze 2 errors      [恢复] [取消]
```

- 默认筛选 `进行中 + 待你决定 + 阻塞`，`已完成` 需手点。
- 每行显示：ID、标题、状态、依赖未满足标记、写域摘要、重试/提问次数、预算。
- 「按计划派发」先调 `queue/plan`，弹出可并行批次确认，不直接批量打出去。
- 手动派发与批量派发都遵守依赖/并行/写域护栏；被拒时行内说明原因。

### 6.2 任务详情（右栏详情页）

点任务行 → 右栏自动切到「任务详情」窗口；关窗口不清选中，再次点同一行重新打开。
窗口与文件/设置共享右栏宿主，窄于 360px 时按宿主规则折叠。

```text
T2 会话列表按项目过滤                      [恢复] [重试] [取消]
状态：执行中 · 第 1 次 · 8.2k tokens · 预算 8.2k/50k
[概览] [计划] [打包] [执行与门控] [消息与专家] [台账]
```

| 页签 | 内容 |
| --- | --- |
| 概览 | 状态、`blocked_reason`、`last_error`、重试/提问、最近决策、记忆来源/hash/是否截断 |
| 计划 | 任务内容（Markdown 可编辑）、需求五栏、验收、依赖、读写域、优先级、`kind`、附件与引用；非终态可编辑 |
| 打包 | `pack.json` 摘要（文件数/字节/基线命令/风险点）、`pack.md` 打开 |
| 执行与门控 | 改动文件、diff 摘要、门控命令与输出（截断+完整路径）、重试历史 |
| 消息与专家 | 打包/执行之间的消息线程、专家调用（问题/结论/依据/未决） |
| 台账 | 该任务全部 `runs`：角色、模型、token、耗时、工具调用、`memory_hash` |

- 详情页只读/可编辑边界按 §6.0.7；编辑保存后就地刷新中栏对应任务行。
- 切换产线时关闭该窗口并清掉选中任务，避免把 A 线任务详情留在 B 线上下文。

### 6.3 主控条与暂停

- `立即决策` 回包展开显示：动作、理由、被哪条护栏降级、是否生效。
- `暂停产线` 立即停止自动派发；已经 `running` 的任务继续跑完，不强制中断。
- `恢复` 写回执行中并立即决策一次。
- 连续 3 次决策失败自动暂停，首屏显示「主控连续失败，已暂停」+ 原因 + 恢复按钮。

### 6.4 记忆与项目知识（直接套 agent）

**结论：直接复用 `tree.agent` 的记忆，不在产线里自建第二套。**
产线只做「消费方」：读记忆走 agent 的端口，写记忆也走 agent 的端口；
产线不读 `.self/memory.md`、不缓存记忆正文、不做自己的记忆裁剪/排序。

#### 6.4.1 三个概念分开

| 概念 | 归属 | 说明 |
| --- | --- | --- |
| **Agent 记忆** | `tree.agent` | 当前 MVP = `.self/memory.md` + 会话压缩摘要；后续升级为结构化/向量记忆也只改 agent |
| **项目文档** | 产线 `line.yaml.docs.memory_manifest` | 明确列出的项目文档（project-status/work-log/known-issues…），是「资料」不是「记忆」 |
| **任务输入** | 产线 `task.yaml` | `brief / acceptance / references / attachments`，只属于本任务 |

> `docs.memory_manifest` 保留原名以兼容存量，但 UI 标为「项目文档」；产线不再把它叫记忆，
> 也不在产线里实现第二套记忆存储。

#### 6.4.2 记忆端口（`tree.agent` 执行站）

| 命令 | 入参 | 回包 | 用途 |
| --- | --- | --- | --- |
| `agent.memory.get` | `{agent_id, purpose: prepare\|pack\|run, budget_chars, kind?}` | `{text, sources[], hash, version, truncated}` | 取**已由 agent 裁剪/排序/格式化**的记忆块 |
| `agent.memory.record` | `{agent_id, source: production_line, line_id, task_id, status, summary, artifacts[], at}` | `{accepted, id?}` | 把任务结果作为记忆候选交给 agent，由 agent 决定是否吸收 |

- `agent_id` 取 `line.yaml.executor.agent_id`（员工身份），不是「谁点了派发」。
- `text` 是 agent 渲染好的 Markdown；产线**不解析、不二次裁剪**，只原样注入提示词。
- `sources` / `hash` / `truncated` 只用于台账与 UI 展示，不落产线数据。
- `version` 供未来记忆升级时做兼容判断；产线不按内部结构分支。
- 记忆不可用（命令缺失/超时）⇒ 空块 + 台账记 `memory_unavailable`，任务继续，不 fail-closed。

#### 6.4.3 注入点与预算

| 场景 | 是否注入 | `purpose` | 默认预算 |
| --- | --- | --- | --- |
| 准备阶段侦查 | ✅ | `prepare` | 4 000 字 |
| 打包（packer） | ✅ | `pack` | 6 000 字 |
| 执行（executor） | ✅ | `run` | 6 000 字 |
| 主控 tick | ❌（v1） | — | — |

- 主控保持「快照决策」，不把记忆塞进每 tick，避免成本与漂移；后续需要时再单列开关。
- 预算由调用方传入，**裁剪由 agent 完成**；产线只显示 `truncated`。
- 同一次任务里打包与执行各自取最新记忆；不把记忆正文写进 `pack.json`。

#### 6.4.4 写入路径

- 任务进入终态（`done / blocked / cancelled`）后，产线调用一次 `agent.memory.record`
  （fire-and-forget，失败只记日志，不影响任务结果）。
- 记录内容只放**结果摘要**：任务标题、状态、改动文件、门控结果、决策动作；
  不放完整对话、不放代码全文、不放附件正文。
- 当前 MVP 由 agent 写入自己的候选队列（agent 自有存储）；**产线不写 `.self/memory.md`**。
  后续 agent 记忆升级时，由 agent 消费候选队列并决定合并策略。

#### 6.4.5 保证「逻辑只存一次」

1. 记忆读取、裁剪、排序、格式化只在 `tree.agent` 的 memory 实现里；
   产线只有一个 `MemoryPort` 适配器（`get/record` 两个方法）。
2. 产线不读 `.self/memory.md`、不存记忆副本、不写记忆文件。
3. 提示词里只有**一个**「## 记忆」段，准备/打包/执行共用，不按角色各写一套格式。
4. `pack.json` / run 台账只存 `memory_hash` 与 `sources`，不存正文。
5. 项目文档读取收敛为一个共享 `projectContext` helper（准备/打包/执行共用），
   与 agent 记忆彻底分开，避免两套「记忆」并行。
6. 未来 agent 记忆升级只改 `tree.agent` 实现；`agent.memory.get/record` 的命令与回包形状保持稳定，
   产线零改动（契约测试钉住形状）。

#### 6.4.6 记忆与任务输入的区别

- 附件/内容变化 ⇒ 旧 `pack` 失效（任务输入变了）。
- 记忆变化 ⇒ **不**让 `pack` 失效；执行用最新记忆，台账同时记录打包与执行两个 `memory_hash`。
- 记忆不是事实真源：状态机、验收、写域仍以 `task.yaml` 为准，记忆只影响提示词。

#### 6.4.7 UI 与验收

- 任务详情「概览」显示：记忆来源数、字数、是否截断、`memory_hash` 前 8 位；
  展开可看 `sources`（路径/章节），不显示全文。
- 台账每条 run 带 `memory_hash` 与 `memory_sources`，便于复盘「当时用了哪份记忆」。
- 验收：同一任务打包/执行提示词都出现记忆块；`pack.json` 无记忆正文；
  agent 记忆升级后产线无需改动即可继续工作；记忆不可用时任务仍能完成并留下原因。

| **逻辑去重** | 状态、进度、模型/维度、降级原因、结果；`运行下一批` / `全量重建` | 折叠 |

- 工具居工作台底部，不占首屏。
- 产物打开复用 files 插件 `line:<id>` 作用域，不新增读取通道。
- 大文件（`pack.json`、门控输出）只显示摘要，正文走文件窗。

## 10. 空态、异常态与依赖态

| 场景 | 界面 | 动作 |
| --- | --- | --- |
| 没有任何产线 | 左栏空态说明 + 「新建产线」 | 创建 |
| 插件未安装/停用 | 全屏可读说明（现有 `productionReadable`） | 去插件管理 |
| 缺 `tree.docnorm` / `tree.agent` / `local_executor` | 产线头下方红色横幅，列出缺失项 | 安装依赖 |
| 未选执行 Agent | 横幅「未配置执行 Agent，无法派发」 | 去配置 |
| 工作空间不存在 / 不是 git 仓 | 预检横幅：打包可跑、执行无法判写域 | 换目录 / 初始化 git |
| 模型池为空或角色模型失效 | 角色卡标红，禁用保存/派发 | 去模型池 |
| 没有任务 | 今日空态 + 「开始准备」 | 进准备 |
| 全部任务终态 | 「本轮完成」摘要 + 产物入口 | 复盘 / 新建任务 |

| 断线/会话失效 | 顶部横幅，不覆盖工作台 | 自动重连 / 重新登录 |

所有空态都要回答「下一步点哪里」，不只写「暂无数据」。

## 11. 交互规则

1. **刷新**：工作台可见时订阅 `broadcast.task_state`；断开或插件未实现推送时 3s 轮询。
   窗口不可见时停轮询，恢复可见时先拉一次 REST 快照。
2. **动作反馈**：按钮就地转圈 + 防重复；失败在卡片/行内显示，不用全屏错误。
3. **确认**：删除产线、取消任务、专家开写工具、改写域需二次确认；其余动作一步完成。
4. **折叠**：今日分区、工具区、详情页签同一时间只展开一个；展开/收起不改变上方内容位置。
5. **滚动**：任务看板与台账虚拟化；详情抽屉独立滚动；工作台整体滚动不嵌套。
6. **返回**：详情抽屉关闭回到列表原位置；准备四步可回退，不丢草稿。
7. **无聊天**：不提供与产线对话的输入框；补充说明只落在对应步骤/任务字段。

## 12. 与现有 UI 平台的约束

- 产线是活动栏第 4 项，与 Agent 并列；切页用 `IndexedStack` 保持会话与工作台状态
  （现有实现已如此）。
- 中栏是工作台唯一承载区；折叠中栏时沿用现有 chevron 机制。
- 右栏继续承载文件窗、设置、插件管理与**任务详情**；任务详情是 `RightPanelEntry`（id `productionTask`，
  `autoOpenOnSelection`），不新增中栏抽屉或第三套详情容器。
- 视觉沿用 `AppRadius`、主题 token、字重/字号设置；状态色用 `ColorScheme`
  的 primary/tertiary/error/secondary，不新增硬编码色值。
- UI 只经 REST/站点与插件通信，不读插件数据目录；产物打开走 files 插件。

## 13. 明确不做

- 不做与产线的聊天流；不做「问产线一句，它直接改需求」。
- 不做无人值守连跑一整天；自动推进只到当前队列跑完。
- 不做跨产线调度、不做产线互调 Agent 会话。
- 不做自动 `commit/push`；只给 diff 摘要与建议提交信息。
- 不做移动端/窄屏专门布局；桌面优先。
- 首版不提供「强制派发」开关；护栏被拒就是被拒。
