## 工作流（workflow）

## 一期骨架实施流程（须用户确认后启用）
1. 需求澄清回填（插件形态/首批场景/UI/接收站权限/数据可靠性）→ 确定实施范围
2. 模块落地：server/plugin/（事件总线、注册表、看门狗、出站 SDK）
3. 埋点接入：白名单起步（工具执行 llm.py / 消息链 chat.py / 活动日志）
4. 示例插件：项目架构分析演示（workspaceIO 读取 + _dispatch_agent_message 推送结果）
5. 测试：隔离反例矩阵 + 异步反例集（见验收基线）；全量 pytest 回归
6. 交付：涉及 server 代码改动需重启后端（高危，先用户确认）；WS 只增不改、前端零改动（已确认）
7. 二期评估：宿主通道（frontend_tunnel/Process 托管常驻化）/join 持久化/只读调试面板

## 该类任务规范

## 设计决策（D1-D9）
- D1 事件信封：{event_id, seq, type, ts, scope四元组, source, payload}；大对象走引用；seq 保序
- D2 隔离：定义共享、实例按 scope 隔离（team⊂agent⊂session 前缀层级，默认 team）；全程四元组自描述键；总线入口+出站出口 fail-closed 校验；策略收后端
- D3 注册表：独立生命周期（禁止与 session_cache LRU 混用）；懒创建+空闲 TTL+Pin 常驻；级联清理（session 删/agent 移除/团队解散）
- D4 广播：白名单显式 publish；scope+type 过滤；有界异步队列+溢出丢弃计数
- D5 中转：注册声明触发点+join 组；join 原语（计数/键值齐备、all/any、组超时、partial 交付+缺项清单、活跃组+队列双上限）；handle sync/async；实例内串行、实例间并行；插件自协调为逃生舱
- D6 接收：SDK 白名单（workspaceIO / _dispatch_agent_message(active=False 防循环) / ws_manager.send_message / 活动日志）+强制 scope 校验
- D7 心跳：复用 tool_exec_progress 看门狗语义（10s 续期/60s 滑窗/判死失效/归属校验 fail-closed）；实例级+处理级两用途；等待齐备期不发（防假活跃）
- D8 WS：只增不改（plugin_event/plugin_status）；前端未知类型安全忽略（已核验，无需前端改动）
- D9 并发：enqueue 即返不阻塞消费线程/事件循环；背压=有界队列+丢弃计数；300+ agent 事件量评估入验收

## 验收基线
- 隔离反例矩阵：跨 user/team/agent/session 四类越权必须拒绝或不可见；清理级联（session/agent/团队）
- 异步反例集：join 部分到达/重复触发/乱序晚到/窗口重叠；心跳真死假死；背压显式；崩溃解除路径防悬挂
- 回归：现有 WS 协议与前端零改动（已确认）；不阻塞主线（消费线程/事件循环）

## 注意事项

- 一期为内存态（不持久化，如实标注）；二期宿主通道/join 深化/只读面板；三期 UI/用户上传插件/沙箱评估
- 关键风险：隔离串扰（中×高）、常驻内存泄漏（高×高，独立注册表+TTL/Pin 缓解）、事件洪泛（白名单+有界队列）、join 泄漏（高×高，组超时+partial+双上限）、心跳误判（fail-closed+等待期不发）
- 待用户澄清 5 项：插件形态（内置 vs 上传）/首批场景清单/UI（共识不做）/接收站权限/数据可靠性（可否丢弃/落盘）
- 产物索引：agentspace/.hard/20260913-plugin-stations/（recon/goal/spec/task/checklist/meeting 01+02+speeches/decisions/ADR）
- 现场观察（供系统参考）：①成员→TOP 消息在长处理轮中分钟级延迟切入（FIFO 最终送达，大任务建议数据库兜底拉取）②成员向 leader 寻址需用 agent ID（名称会被 cross_top_denied）③本地执行器间歇"已注销"（WS 断连已知问题，影响 grep/terminal）
